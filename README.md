# 선교편지 — 시작 폴더

선교사가 후원자와 후원교회에 보낼 편지를 만들고 공유하는 웹앱입니다.
**서버도, 데이터베이스도, 비용도 필요하지 않습니다.**

- 편지 본문은 **비밀번호로 암호화**되어 저장됩니다. 저장소가 공개여도 내용이 노출되지 않습니다.
- 사진은 **구글 드라이브 공유 링크**를 붙여넣어 넣습니다.
- 후원자는 **링크 하나**로 읽고, **A4 PDF**로 저장할 수 있습니다.
- 앱은 **GitHub 토큰을 쓰지 않습니다.** 발행은 명령 한 줄로 합니다.

이 폴더는 **아무 내용도 들어 있지 않은 시작본**입니다. 아래 순서대로 하시면 됩니다.

---

## 미리 깔아 둘 것

| | 무엇 | 어디서 |
|---|---|---|
| 1 | **Git** | [git-scm.com/downloads](https://git-scm.com/downloads) |
| 2 | **Node.js** (편지 발행에 필요) | [nodejs.org](https://nodejs.org) — LTS 버전 |

**윈도우**에서는 설치 후 **Git Bash**(설치 시 함께 깔립니다)를 열어 명령을 실행하세요.
이 문서의 명령이 그대로 동작합니다. 명령 프롬프트(cmd)를 쓰신다면 아래를 참고하세요.

| 이 문서 | 명령 프롬프트에서는 |
|---|---|
| `~/Downloads/letter-2026-09.json` | `%USERPROFILE%\Downloads\letter-2026-09.json` |
| `python3 -m http.server 4173` | `py -m http.server 4173` |

**맥**에서는 터미널을 그대로 쓰시면 됩니다.

설치가 됐는지 확인:

```bash
git --version
node --version
```

## 처음 한 번만 (약 15분)

### 1. 저장소 만들고 이 폴더 올리기

[github.com/new](https://github.com/new) 에서 저장소를 만듭니다. 이름은 예를 들어 `letters`.
**Public** 으로 두어도 됩니다 — 편지는 암호화되어 저장됩니다.

이 폴더를 복사한 뒤, 복사한 폴더 안에서:

```bash
git init -b main
git add .
git commit -m "선교편지 시작"
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

### 2. GitHub Pages 켜기

저장소 → **Settings → Pages** → Source 를 **Deploy from a branch**,
Branch 를 **main / (root)** 로 두고 저장합니다.
1~2분 뒤 `https://<계정>.github.io/<저장소>/` 가 열립니다.

### 3. 설정 채우기

열린 주소에서 **설정** 화면으로 들어가 채웁니다.

| 항목 | 설명 |
|---|---|
| 이름 | 편지에 "보내는 이"로 나옵니다 |
| 발행처 · 로고 | 교회나 선교회 이름과 로고 (선택) |
| 맺음 사진 | 편지 맨 끝에 작은 원형으로 (선택) |
| 저장소 | 1번에서 만든 소유자·저장소 이름 |
| 기본 비밀번호 | 새 편지에 자동으로 채워집니다 |
| 후원 안내 | 계좌 정보 — 편지와 함께 암호화됩니다 |

이 값들은 **그 브라우저에만** 저장됩니다. 늘 쓰는 컴퓨터에서 한 번 해 두세요.

### 4. 로고·사진 넣기 (선택)

`assets/img/` 폴더에 `logo.png`, `portrait.png` 를 넣고 커밋·푸시한 뒤,
설정 화면에 `assets/img/logo.png` 처럼 경로를 적으면 됩니다.

## 매달 하는 일

1. **새 편지** → 제목과 본문을 씁니다. 쓰는 동안 자동으로 임시저장됩니다.
2. **사진 추가** → 구글 드라이브 공유 링크를 붙여넣습니다. 한 줄에 1·2·3장을 고를 수 있습니다.
3. **미리보기** 로 후원자에게 보일 모습을 확인합니다.
4. **발행 파일 내려받기** → `letter-2026-09.json` 이 다운로드 폴더에 받아집니다.
5. 이 폴더에서 명령 한 줄:

```bash
node scripts/publish-letter.mjs ~/Downloads/letter-2026-09.json
```

암호화 → `letters/` 기록 → 커밋 → 푸시까지 한 번에 끝납니다.
(`--no-push` 를 붙이면 파일만 쓰고 멈춥니다.)

6. 후원자에게 **링크와 비밀번호**를 함께 보냅니다.

```
https://<계정>.github.io/<저장소>/#/letter/2026-09
비밀번호: ○○○○
```

같은 월로 다시 발행하면 **수정**됩니다. 링크는 그대로입니다.

> **받은 발행 파일은 발행 뒤 지우세요.** 그 안에는 비밀번호가 그대로 적혀 있습니다.
> 특히 이 프로젝트 폴더 안으로 옮기지 마세요.

## 사진이 후원자에게 안 보인다면

가장 흔한 문제입니다. 드라이브에서 사진의
**공유 → 일반 액세스 → '링크가 있는 모든 사용자'** 로 바꿔 주세요.

> 선교사님은 구글에 로그인되어 있어서 설정이 잘못돼도 화면에는 사진이 보입니다.
> 확인하려면 **시크릿 창**으로 편지 링크를 열어 보세요.

## 알아 두실 점

- **비밀번호를 잊으면 그 편지는 다시 열 수 없습니다.** 복구 수단이 없습니다.
- 비밀번호는 **8자 이상, 글자와 숫자를 섞어** 주세요. 생일 같은 숫자만으로는
  내려받아 대입하면 몇 시간 안에 풀립니다. 힌트에 "생일"처럼 형식을 알려주는 말도 피하세요.
- **사진은 암호화되지 않습니다.** 드라이브에서 공개로 제공되므로 링크를 아는 사람은 볼 수 있습니다.
- 발행 날짜와 편지 개수는 저장소에서 드러납니다. 내용과 제목은 드러나지 않습니다.
- 발행 후 GitHub Pages 반영에 **최대 1분**이 걸립니다.

## 만드는 사람을 위한 메모

서버 없는 정적 웹앱입니다. 빌드 단계가 없습니다.

```bash
python3 -m http.server 4173     # 윈도우 명령 프롬프트: py -m http.server 4173
```

`http://localhost:4173` 로 열면 됩니다. 암호화(WebCrypto)는 HTTPS 또는 localhost 에서만 동작합니다.
파일을 더블클릭해서 여는 `file://` 방식으로는 동작하지 않습니다.

CSS 를 고쳤다면 커밋 전에 한 번:

```bash
node scripts/bump-assets.mjs
```

`index.html` 의 `app.css?v=…` 를 파일 내용 해시로 바꿔, 후원자 브라우저에 옛 CSS 가 남지 않게 합니다.

| 파일 | 역할 |
|---|---|
| `assets/js/crypto.js` | PBKDF2 + AES-GCM 암·복호화 |
| `assets/js/render.js` | 편지 렌더링·인쇄 (보기/미리보기 공용) |
| `assets/js/letters.js` | 편지 데이터 계층 |
| `assets/js/drive.js` | 드라이브 링크 파싱·검증 |
| `assets/js/views/` | 화면 4개 (목록·작성·설정·읽기) |
| `scripts/publish-letter.mjs` | 편지 암호화 + 발행 (브라우저 없이) |
| `scripts/bump-assets.mjs` | CSS 캐시 무효화 |

`assets/js/crypto.js` 를 고치면 `scripts/publish-letter.mjs` 의 암호화도 같이 맞춰야 합니다.
Node 쪽 자체 테스트로 끝내지 말고, **브라우저에서 실제로 편지를 열어** 왕복 확인하세요.
이 호환이 깨지면 이미 발행한 편지를 아무도 열 수 없게 됩니다.
